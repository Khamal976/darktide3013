Ошибка 3013: причины, диагностика и исправление

Не определяйте причину только по номеру ошибки. Разделяйте отказ входа, неудачное подключение к хабу и разрыв уже установленной игровой сессии. Ниже — признаки в логе и настройка обхода для каждого этапа.

Разбор сделан на реальном ПК (Windows 11, Steam, роутер OpenWrt с Passwall 2). Всё, что помечено «проверено», воспроизведено и подтверждено логом игры. Остальное собрано из гайдов сообщества и не проверялось.

1. Что на самом деле стоит за 3013

Здесь рассмотрены несколько сетевых причин. Коды в интерфейсе и названия ошибок в console-логе могут различаться: читайте последнюю успешно пройденную стадию и причину отказа.

Причина AСоединение со службой входа или backend не устанавливается вовремя. Исторически наблюдался TLS-тайм-аут Schannel; в новых логах также есть Connection timed out. Это симптом соединения, не автоматическое доказательство фильтрации CloudFront. Текущий identity-endpoint — login.shr-prod-identity.fatshark.services.
Причина BНе выполнена проверка отзыва сертификата. Эту ветку проверяйте при явной CRYPT_E_REVOCATION_OFFLINE. В исторической конфигурации помогал прямой маршрут Amazon Trust. В последнем логе этой сигнатуры нет; правило Direct не является универсальным требованием для любых сетей.
Причина CНе доходит UDP до хаб-сервера. После выбора персонажа игра ищет сервер Морнингстара по голому IP на UDP-порту 355xx. Сервера стоят в AWS (Франкфурт, Ирландия, Стокгольм), и UDP до них из России не проходит. Симптом: экран выбора персонажа открывается, а после выбора всегда 3013.

Причины могут накладываться. После завершения входа отдельно проверяйте подключение к игровому серверу и удержание сессии. DNS исключён автором как причина текущего сбоя; смена резолвера и очистка кэша не предлагаются как его исправление.

Блокировка мигает. Фильтрация UDP до AWS то включается, то пропадает: у одного и того же провайдера в один день игра заходит сама, на следующий снова 3013. Это подтверждено прямым замером с одного ПК: 9–10 сентября UDP до AWS не проходил вообще, 11 сентября тот же тест пошёл напрямую, без обхода. Отсюда два вывода. Если 3013 «сам прошёл», не удаляйте обход, он понадобится, когда блок вернётся. И наоборот, если ничего не помогает, имеет смысл просто попробовать позже: возможно, поймали активную фазу.

4. Самое простое: готовый файл для zapret по отчётам игроков работает

Если у вас установлен zapret (Flowseal/zapret-discord-youtube), генератор добавляет игровые UDP-порты и создаёт варианты стратегий. Стратегию нужно проверять на своей сети; успешный запуск winws не гарантирует успешный вход или удержание хаба.

Скачать zapret-darktide.zip

Обновление списка доменов. Перед запуском проверьте darktide-setup.ps1. Массив должен выглядеть так:

$domains = @('atoma.cloud','atoma-discovery.com','fatshark.services')

Для старого архива замените массив вручную, затем повторно запустите setup. В lists\list-general-user.txt должны быть:

atoma.cloud
atoma-discovery.com
fatshark.services

Узкую запись login.shr-prod-identity.fatshark.services можно удалить как избыточную. Генератор её автоматически не удаляет. Сохраните вручную изменённые darktide*.bat до перегенерации, затем перезапустите стратегию и игру. Редакция страницы сама по себе не обновляет ZIP по ссылке.

  1. Распакуйте архив. Файлы darktide-setup.bat и darktide-setup.ps1 положите в папку zapret, рядом с general.bat.
  2. Запустите darktide-setup.bat двойным щелчком. Он добавит домены игры в lists\list-general-user.txt и создаст darktide.bat, darktide (ALT).bat, darktide (ALT2).bat и так далее, по одному на каждую стратегию из папки.
  3. Запустите darktide.bat с правами администратора. capture is started подтверждает запуск перехвата, не успешность обхода. Не закрывайте окно во время проверки игры.
  4. Если 3013 остался, закройте окно и берите следующий: darktide (ALT).bat, ALT2, ALT3 и далее. Стратегия подбирается под провайдера так же, как для YouTube. Если у вас работает general (ALT11).bat, берите darktide (ALT11).bat.
  • Если winws остановился: прочитайте сообщение об ошибке. winws has STOPPED может означать проблему параметров, прав, драйвера или конфликт — не только неподходящую стратегию. Создаваемые BAT останавливают все winws.exe и выполняют stop/delete службы WinDivert; учитывайте другие работающие экземпляры.
  • Свежая сборка подходит как есть. Ничего доустанавливать не нужно: генератор использует PowerShell, встроенный в Windows, и файлы самой сборки. Проверено на 1.10.0 и 1.10.2, в сборках старше 1.9 нет bin\stun.bin.
  • После обновления zapret новая версия лежит в новой папке, и darktide*.bat туда не переезжают. Скопируйте в неё те же два файла и запустите darktide-setup.bat ещё раз.

Что делает правка и почему это работает

Каждый darktide*.bat это копия соответствующего general*.bat с тремя отличиями. Порты 35000–36000, на которых живут хаб- и игровые серверы Darktide, добавлены в перехват UDP. Первым профилем стоит правило: перед первыми пакетами игры на эти порты zapret отправляет поддельный STUN-запрос (bin\stun.bin). И в профиле Game Filter, если он есть в стратегии, фейк ACTIVE_GAME_UDP.bin заменён на тот же stun.bin.

В отчётах игроков замена игрового fake payload на STUN помогала пройти фильтрацию. Объяснение через классификацию первого пакета DPI — предполагаемый механизм, а не доказанное устройство ТСПУ. Работоспособность зависит от сети и стратегии.

Замена ACTIVE_GAME_UDP.bin на stun.bin это находка игрока Арадиэла из обсуждения в Steam: у него заработало 11.09.2026 на стратегии ALT11 с включённым Game Filter (TCP и UDP). Архив выше делает то же самое автоматически и не требует включать Game Filter, потому что правило для портов игры добавлено отдельно.

Статус. Механика подтверждена отчётами игроков, файлы из архива проверены на генерацию, но полный цикл «прямой путь через провайдера + darktide.bat + вход в хаб» на моём ПК ещё не прогнан: у меня AWS идёт через роутер. Как только прогоню, отметка сменится на «проверено». Сработало у вас или нет, напишите в тему Steam, какая стратегия и какой провайдер.

5. Исправление через роутер (OpenWrt + Passwall 2) исторический тест

Самый надёжный путь: весь обход делает роутер, на ПК ничего не ставится. Схема применима к любому прокси с правилами по доменам и IP (sing-box, xray, HomeProxy, Podkop), названия полей будут отличаться.

Шаг 1. Домены игры в туннель

Если службы игры должны идти через зарубежный узел, добавьте следующие домены. Проверьте фактический outbound и приоритет исключений; наличие строки само по себе не подтверждает исправление.

domain:atoma.cloud
domain:atoma-discovery.com
domain:fatshark.services

Шаг 2. Amazon Trust напрямую

Создайте правило выше правила прокси с узлом «Direct Connection» и доменом:

domain:amazontrust.com

В исторической конфигурации Direct для Amazon Trust устранял ошибку отзыва. Это не универсальный запрет туннеля: при явной ошибке проверьте доступ к URL фактической цепочки сертификатов через используемый маршрут. В последнем логе явной ошибки отзыва нет.

Шаг 3. Подсети AWS в туннель по TCP и UDP

Хаб ищется по IP:порту; нужны правила для игрового UDP, если его следует направлять через узел. Три исторических примера ниже не являются достаточным списком: они покрывают лишь 1 из 9 уникальных игровых IP логов 29.09–01.10. Полный список ниже покрывает все 9.

6. Другие варианты на ПК не проверено

Если роутера с прокси нет, а zapret из раздела 4 не вытянул причину C ни на одной стратегии, обход UDP нужно поднять на самом компьютере. Обычный клиент Cloudflare WARP не работает: оба его протокола, MASQUE и WireGuard, блокируются (проверено, подключение не устанавливается ни на одном порту).

Рабочий вариант из гайдов сообщества: AmneziaVPN с конфигом WARP через AmneziaWG-обфускацию (конфиг генерируется на warpgen.net или аналогах). Этот путь мной не проверялся, но именно он описан в актуальных Steam-гайдах по 3013. После подключения прогоните STUN-тест из раздела 7: первая строка должна стать REPLY. Любой другой VPN-клиент на ПК подойдёт при том же условии: он должен пропускать UDP, и его сервер должен дотягиваться до AWS.

7. Проверка без запуска игры

Три проверки, каждая на свою причину. Запускать в PowerShell.

Причина A: TLS к серверу авторизации

Проверяйте текущий identity-endpoint. HTTP 401/403/404 без игровых учётных данных может подтверждать достижимость HTTP-службы, но не вход в игру. code=000 означает отсутствие HTTP-статуса и не устанавливает причину. Для неудачного запроса нужен подробный вывод -v.

curl.exe -4 -sS -o NUL -m 30 -w "auth: code=%{http_code} time=%{time_total}s`n" https://login.shr-prod-identity.fatshark.services/

Причина B: серверы отзыва Amazon

Следующий GET проверяет только HTTP-ответ хоста, не статус отзыва сертификата. HTTP 200 на корневом URL не заменяет корректный OCSP-запрос. Разбирайте проверку отзыва по явной ошибке Schannel и URL фактической цепочки.

curl.exe -4 -s -o NUL -m 12 -w "amazontrust: code=%{http_code} time=%{time_total}s`n" http://ocsp.r2m02.amazontrust.com/

Причина C: UDP до AWS

Сохраните как stun_test.ps1 и запустите в PowerShell. Это предварительная проба двух конкретных STUN-endpoint на UDP 3478. Их текущая доступность здесь не проверена. Отсутствие ответа двух серверов не доказывает блокировку всего UDP.

$targets = @(@('18.156.18.145',3478,'AWS eu-central-1'), @('46.225.95.169',3478,'Hetzner DE, контроль'))
foreach ($t in $targets) {
  $ip,$port,$name = $t
  $u = New-Object System.Net.Sockets.UdpClient
  $u.Client.ReceiveTimeout = 4000
  $u.Connect($ip, $port)
  $b = [byte[]](0,1,0,0,0x21,0x12,0xA4,0x42) + [byte[]](1..12)
  [void]$u.Send($b, $b.Length)
  $ep = New-Object System.Net.IPEndPoint([System.Net.IPAddress]::Any, 0)
  try   { $r = $u.Receive([ref]$ep); Write-Host ("{0,-24} {1}:{2}  REPLY {3} bytes" -f $name,$ip,$port,$r.Length) }
  catch { Write-Host ("{0,-24} {1}:{2}  NO REPLY" -f $name,$ip,$port) }
  finally { $u.Close() }
}

Ответ STUN на UDP 3478 не гарантирует подключение Darktide к другому IP на 355xx. Скрипт помечает любой полученный пакет как REPLY без проверки типа и transaction ID. Итог проверяйте в игре: удержание хаба, миссия и возвращение. DNS исключён как причина текущего сбоя; тестов смены DNS здесь нет.

8. Что не помогает

  • Клиент Cloudflare WARP. Заблокирован на уровне протокола, не подключается.
  • Смена DNS и ipconfig /flushdns. По уточнению автора DNS не является причиной текущей проблемы. Эти действия не предлагаются как исправление наблюдаемых отказов входа и игровых разрывов. Сам тайм-аут этапа не устанавливает первопричину.
  • Отключение Nvidia Reflex. Совет из англоязычных гайдов, к сетевой причине отношения не имеет.
  • Отключение проверки отзыва сертификатов в Windows. Снимает причину B, но ослабляет безопасность всей системы. Правило «amazontrust.com напрямую» делает то же без побочных эффектов.
  • Только домены в прокси-списке. Хаб ищется по IP через UDP, доменные правила его не ловят. Без IP-правил и узла с UDP причина C остаётся.

Error 3013: causes, diagnosis and fixes

Do not infer the cause from the error number alone. Distinguish failed sign-in, failed hub connection and loss of an established game session. Below are the log signatures and workaround settings for each stage.

1. What is really behind 3013

This guide covers several network causes. The on-screen code and console-log error name may differ: identify the last completed stage and the reported failure reason.

Cause AThe connection to identity or backend does not complete in time. Historical tests showed a Schannel TLS timeout; newer logs also contain Connection timed out. This is a connection symptom, not automatic proof of CloudFront filtering. The current identity endpoint is login.shr-prod-identity.fatshark.services.
Cause BCertificate revocation checking fails. Investigate this branch when CRYPT_E_REVOCATION_OFFLINE is explicitly reported. Direct routing for Amazon Trust helped the historical setup. This signature is absent from the latest log; Direct is not a universal requirement for every network.
Cause CUDP does not reach the hub server. After character select the game looks for the Mourningstar server by bare IP on UDP port 355xx. Those servers live in AWS (Frankfurt, Ireland, Stockholm), and UDP to them does not get through from Russia. Symptom: the character screen opens, then 3013 every time after picking one.

Causes can overlap. After sign-in succeeds, check the game-server connection and session stability separately. The author has ruled out DNS as the cause of the current issue; changing resolvers or flushing the cache is not proposed as its fix.

The block flickers. UDP filtering to AWS comes and goes: on the same ISP the game connects on its own one day and returns 3013 the next. Confirmed by a direct measurement from one PC: on 9–10 September UDP to AWS did not pass at all, on 11 September the same test went through directly, with no workaround. Two takeaways. If 3013 "fixed itself", do not remove your workaround, you will need it when the block returns. And the other way round, if nothing helps, it is worth simply trying again later: you may have hit an active phase.

4. Easiest: a drop-in file for zapret works per player reports

If you run zapret (Flowseal/zapret-discord-youtube), the generator adds the game UDP ports and creates strategy variants. Test the selected strategy on your network; starting winws does not guarantee successful sign-in or a stable hub session.

Download zapret-darktide.zip

Domain-list update. Check darktide-setup.ps1 before running it. The array must be:

$domains = @('atoma.cloud','atoma-discovery.com','fatshark.services')

For an older archive, replace the array manually and rerun setup. lists\list-general-user.txt must contain:

atoma.cloud
atoma-discovery.com
fatshark.services

The narrower login.shr-prod-identity.fatshark.services entry is redundant and may be removed manually; setup does not remove it automatically. Back up manually edited darktide*.bat before regenerating them, then restart the strategy and game. Updating this page does not update the linked ZIP archive.

  1. Unpack the archive. Put darktide-setup.bat and darktide-setup.ps1 into the zapret folder, next to general.bat.
  2. Double-click darktide-setup.bat. It adds the game's domains to lists\list-general-user.txt and creates darktide.bat, darktide (ALT).bat, darktide (ALT2).bat and so on, one per strategy in the folder.
  3. Run darktide.bat as administrator. capture is started confirms packet capture, not a successful bypass. Keep the window open during the game test.
  4. If 3013 persists, close the window and take the next one: darktide (ALT).bat, ALT2, ALT3 and so on. The strategy has to match your ISP, exactly as for YouTube. If general (ALT11).bat works for you, use darktide (ALT11).bat.
  • If winws stops: read the error message. winws has STOPPED can indicate parameters, permissions, driver problems or a conflict, not just an unsuitable strategy. Generated BAT files stop all winws.exe instances and stop/delete the WinDivert service; account for other running instances.
  • A fresh build works as is. Nothing extra to install: the generator uses the PowerShell built into Windows and the build's own files. Verified on 1.10.0 and 1.10.2; builds older than 1.9 lack bin\stun.bin.
  • After updating zapret the new version sits in a new folder and the darktide*.bat files do not move with it. Copy the same two files there and run darktide-setup.bat again.

What the change does and why it works

Each darktide*.bat is a copy of the matching general*.bat with three differences. Ports 35000–36000, where Darktide's hub and game servers live, are added to the UDP capture. The first profile is a rule that sends a fake STUN request (bin\stun.bin) ahead of the game's first packets to those ports. And in the Game Filter profile, where the strategy has one, the ACTIVE_GAME_UDP.bin fake is replaced with the same stun.bin.

Players reported that replacing the game fake payload with STUN helped bypass filtering. First-packet DPI classification is a proposed explanation, not proof of the exact TSPU implementation. Results depend on the network and strategy.

Swapping ACTIVE_GAME_UDP.bin for stun.bin is a find by the player Aradiel in the Steam discussion: it worked for them on 11 Sep 2026 with strategy ALT11 and Game Filter (TCP and UDP) enabled. The archive above does the same automatically and does not require enabling Game Filter, because the rule for the game's ports is added separately.

Status. The mechanism is confirmed by player reports and the archive's output is verified, but the full cycle "direct ISP path + darktide.bat + entering the hub" has not been run on my PC yet: my AWS traffic goes through the router. Once it is, this tag becomes "verified". Whether it worked for you or not, post your strategy and ISP in the Steam thread.

5. Fix on the router (OpenWrt + Passwall 2) historical test

The most reliable path: the router does all the bypassing, nothing is installed on the PC. The scheme applies to any proxy with domain and IP rules (sing-box, xray, HomeProxy, Podkop); field names will differ.

Step 1. Game domains into the tunnel

If game services should use the foreign node, add the following domains. Check the actual outbound and rule priority; adding an entry alone does not prove a fix.

domain:atoma.cloud
domain:atoma-discovery.com
domain:fatshark.services

Step 2. Amazon Trust goes direct

Create a rule above the proxy rule with the node set to "Direct Connection" and the domain:

domain:amazontrust.com

Direct routing for Amazon Trust resolved revocation errors in the historical setup. This is not a universal ban on tunneling: when explicitly reported, check the actual certificate chain URLs through the selected route. The latest log has no explicit revocation error.

Step 4. The node must carry UDP

Test the actual setup. The node must carry and sustain game UDP. VLESS, WebSocket or whitelist labels alone do not establish UDP support: UDP can be carried inside a TCP transport, while limitations depend on configuration and service. STUN is a preliminary probe, not a guarantee that the game server will work.

6. Other options on the PC not tested

If you have no router with a proxy and zapret from section 4 did not solve cause C on any strategy, the UDP bypass has to run on the PC itself. The regular Cloudflare WARP client does not work: both of its protocols, MASQUE and WireGuard, are blocked (verified: it fails to connect on every port).

The working option from community guides: AmneziaVPN with a WARP config over AmneziaWG obfuscation (the config is generated on warpgen.net or similar). I did not test this path myself, but it is the one described in the current Steam guides for 3013. After connecting, run the STUN test from section 7: the first line must become REPLY. Any other VPN client on the PC will do under the same condition: it must carry UDP, and its server must be able to reach AWS.

7. Checks without launching the game

Three checks, one per cause. Run in PowerShell.

Cause A: TLS to the auth server

Probe the current identity endpoint. HTTP 401/403/404 without game credentials may confirm HTTP reachability, not game sign-in. code=000 means no HTTP status was received and does not identify the cause. Use -v for a failed request.

curl.exe -4 -sS -o NUL -m 30 -w "auth: code=%{http_code} time=%{time_total}s`n" https://login.shr-prod-identity.fatshark.services/

Cause B: Amazon revocation servers

The following GET probes only the host’s HTTP response, not certificate revocation status. HTTP 200 at the root URL is not a valid OCSP check. Investigate revocation using an explicit Schannel error and the actual certificate chain URLs.

curl.exe -4 -s -o NUL -m 12 -w "amazontrust: code=%{http_code} time=%{time_total}s`n" http://ocsp.r2m02.amazontrust.com/

Cause C: UDP to AWS

Save as stun_test.ps1 and run it in PowerShell. This is a preliminary probe of two specific STUN endpoints on UDP 3478. Their current availability has not been checked here. Two silent servers do not prove all UDP is blocked.

$targets = @(@('18.156.18.145',3478,'AWS eu-central-1'), @('46.225.95.169',3478,'Hetzner DE, control'))
foreach ($t in $targets) {
  $ip,$port,$name = $t
  $u = New-Object System.Net.Sockets.UdpClient
  $u.Client.ReceiveTimeout = 4000
  $u.Connect($ip, $port)
  $b = [byte[]](0,1,0,0,0x21,0x12,0xA4,0x42) + [byte[]](1..12)
  [void]$u.Send($b, $b.Length)
  $ep = New-Object System.Net.IPEndPoint([System.Net.IPAddress]::Any, 0)
  try   { $r = $u.Receive([ref]$ep); Write-Host ("{0,-24} {1}:{2}  REPLY {3} bytes" -f $name,$ip,$port,$r.Length) }
  catch { Write-Host ("{0,-24} {1}:{2}  NO REPLY" -f $name,$ip,$port) }
  finally { $u.Close() }
}

A STUN reply on UDP 3478 does not guarantee Darktide connectivity to another IP on 355xx. This script labels any received packet REPLY without validating its type or transaction ID. Verify the actual result in-game: stable hub, mission and return. DNS is ruled out as the cause of the current issue; no DNS-change tests are proposed here.

8. What does not help

  • The Cloudflare WARP client. Blocked at the protocol level, does not connect.
  • Changing DNS and ipconfig /flushdns. The author has ruled out DNS as the cause of the current issue. These actions are not proposed as a fix for the observed sign-in failures and game disconnects. A stage timeout alone does not establish the root cause.
  • Disabling Nvidia Reflex. A tip from English-language guides; unrelated to the network cause.
  • Disabling certificate revocation checking in Windows. Removes cause B but weakens security system-wide. The "amazontrust.com direct" rule does the same with no side effects.
  • Domains only in the proxy list. The hub is found by IP over UDP; domain rules never match it. Without IP rules and a node that carries UDP, cause C remains.

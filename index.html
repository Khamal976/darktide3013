Ошибка 3013: три причины под одним кодом и как их чинить

Код 3013 игра выдаёт на любой сетевой сбой между авторизацией и входом в хаб. Под ним у игроков из России прячутся три разные поломки, и лечатся они по-разному. Ниже: как по логу узнать свою, и что делать с каждой.

Разбор сделан на реальном ПК (Windows 11, Steam, роутер OpenWrt с Passwall 2). Всё, что помечено «проверено», воспроизведено и подтверждено логом игры. Остальное собрано из гайдов сообщества и не проверялось.

  2. Определяем свою причину по логу
  3. Куда ходит игра
  4. Исправление через роутер (OpenWrt + Passwall 2)
  5. Исправление только на ПК
  6. Проверка без запуска игры
  7. Что не помогает

1. Что на самом деле стоит за 3013

Игра проходит три сетевых этапа, и любой из них может сорваться в 3013.

Причина AАвторизация не доходит до сервера. Серверы Fatshark (*.atoma.cloud) живут на AWS CloudFront. Провайдер пропускает TCP, но режет TLS-рукопожатие к CloudFront: соединение зависает на 60 секунд и обрывается. Симптом: 3013 сразу на экране входа.
Причина BWindows не может проверить сертификат сервера. Перед TLS Windows ходит за списками отзыва на *.amazontrust.com по обычному HTTP. Если этот трафик завёрнут в VPN-туннель, который до Amazon не дотягивается, авторизация падает с ошибкой отзыва. Симптом: вход проходит «со второго-третьего раза», иногда вообще нет.
Причина CНе доходит UDP до хаб-сервера. После выбора персонажа игра ищет сервер Морнингстара по голому IP на UDP-порту 355xx. Сервера стоят в AWS (Франкфурт, Ирландия, Стокгольм), и UDP до них из России не проходит. Симптом: экран выбора персонажа открывается, а после выбора всегда 3013.

Причины накладываются. Обычно сначала видно A, после её лечения проявляется B, после B остаётся C. Поэтому «исправил, а 3013 всё равно» чаще всего значит, что вылечена не та причина.

2. Определяем свою причину по логу

Игра пишет подробный лог. Откройте папку (вставьте путь в адресную строку проводника):

%APPDATA%\Fatshark\Darktide\console_logs

Возьмите самый свежий файл console-ГГГГ-ММ-ДД-….log и найдите в нём строки из таблицы. Ищите по короткому фрагменту, он выделен.

4. Исправление через роутер (OpenWrt + Passwall 2) проверено

Самый надёжный путь: весь обход делает роутер, на ПК ничего не ставится. Схема применима к любому прокси с правилами по доменам и IP (sing-box, xray, HomeProxy, Podkop), названия полей будут отличаться.

Шаг 1. Домены игры в туннель

В правило, которое идёт на зарубежный узел, добавьте домены. Это закрывает причину A.

domain:atoma.cloud
domain:atoma-discovery.com

Шаг 2. Amazon Trust напрямую

Создайте правило выше правила прокси с узлом «Direct Connection» и доменом:

domain:amazontrust.com

Это закрывает причину B. Направлять эти хосты через туннель нельзя: с большинства зарубежных узлов они не отвечают, и Windows считает проверку отзыва проваленной.

Шаг 3. Подсети AWS в туннель по TCP и UDP

Хаб ищется по IP, домена нет, поэтому нужны IP-правила. Создайте правило на зарубежный узел с Network = «TCP и UDP» и вставьте подсети. Три самых частых:

В Passwall 2 также проверьте: Forwarding Settings → TCP Redir Ports и UDP Redir Ports = All.

Шаг 4. Узел обязан пропускать UDP

Главная ловушка. Узлы-«whitelist» (VLESS + WebSocket через российский фронт-релей с подменой SNI) пропускают TCP и не пропускают UDP. С таким узлом шаги 1–3 выполнены, авторизация проходит, а хаб всё равно даёт 3013. Проверьте узел STUN-тестом из раздела 6 до того, как искать ошибку в правилах. Если UDP не идёт, нужен другой узел: VLESS Reality напрямую, Hysteria2, TUIC, WireGuard или AmneziaWG.

Итог на реальной конфигурации

После четырёх шагов лог показал Found lobby, joining..., Joined lobby, вход в хаб. Ошибок авторизации и отзыва сертификатов ноль. Выход туннеля в Швеции, хаб в Стокгольме, пинг рабочий.

5. Исправление только на ПК частично проверено

Если роутера с прокси нет, обход нужно поднять на самом компьютере. Здесь два разных инструмента под разные причины.

Причина A: zapret

zapret (сборка Flowseal/zapret-discord-youtube) обходит DPI-фильтрацию TLS и закрывает причину A. В файл lists/list-general-user.txt добавьте две строки, затем запустите general.bat от администратора. Если не помогло, перебирайте варианты general (ALT).bat, ALT2 и далее:

atoma.cloud
atoma-discovery.com

Домен cloudfront.net в общем списке zapret уже есть. Проверить, что заработало, можно первой командой из раздела 6. zapret не решает причину C: UDP до хабов он не пробрасывает.

Причина C: VPN на ПК с UDP

Обычный клиент Cloudflare WARP не работает: оба его протокола, MASQUE и WireGuard, блокируются (проверено, подключение не устанавливается ни на одном порту). Рабочий вариант из гайдов сообщества: AmneziaVPN с конфигом WARP через AmneziaWG-обфускацию (конфиг генерируется на warpgen.net или аналогах). Этот путь мной не проверялся, но именно он описан в актуальных Steam-гайдах по 3013. После подключения прогоните STUN-тест из раздела 6: первая строка должна стать REPLY.

6. Проверка без запуска игры

Три проверки, каждая на свою причину. Запускать в PowerShell.

Причина A: TLS к серверу авторизации

Норма: code=404 меньше чем за секунду. Поломка: code=000 и 15–60 секунд.

curl.exe -4 -s -o NUL -m 30 -w "auth: code=%{http_code} time=%{time_total}s`n" https://bsp-auth-prod.atoma.cloud/

Причина B: серверы отзыва Amazon

Норма: code=200 за доли секунды.

curl.exe -4 -s -o NUL -m 12 -w "amazontrust: code=%{http_code} time=%{time_total}s`n" http://ocsp.r2m02.amazontrust.com/

Причина C: UDP до AWS

Сохраните как stun_test.ps1 и запустите powershell -ExecutionPolicy Bypass -File stun_test.ps1. Первая строка проверяет UDP до сервера в AWS Франкфурт тем же путём, каким игра ищет хаб. Вторая, контрольная, до сервера вне AWS: если молчит и она, UDP порезан целиком.

$targets = @(@('18.156.18.145',3478,'AWS eu-central-1'), @('46.225.95.169',3478,'Hetzner DE, контроль'))
foreach ($t in $targets) {
  $ip,$port,$name = $t
  $u = New-Object System.Net.Sockets.UdpClient
  $u.Client.ReceiveTimeout = 4000
  $u.Connect($ip, $port)
  $b = [byte[]](0,1,0,0,0x21,0x12,0xA4,0x42) + [byte[]](1..12)
  [void]$u.Send($b, $b.Length)
  $ep = New-Object System.Net.IPEndPoint([System.Net.IPAddress]::Any, 0)
  try   { $r = $u.Receive([ref]$ep); Write-Host ("{0,-24} {1}:{2}  REPLY {3} bytes" -f $name,$ip,$port,$r.Length) }
  catch { Write-Host ("{0,-24} {1}:{2}  NO REPLY" -f $name,$ip,$port) }
  finally { $u.Close() }
}

Это STUN-запрос: сервер просто отвечает, откуда его видит. Если строка AWS даёт REPLY, хаб подключится.

7. Что не помогает

  • Клиент Cloudflare WARP. Заблокирован на уровне протокола, не подключается.
  • ipconfig /flushdns, смена DNS на 8.8.8.8, проверка файлов игры. Проблема не в DNS и не в файлах: имена резолвятся, TLS и UDP режутся на пути.
  • Отключение Nvidia Reflex. Совет из англоязычных гайдов, к сетевой причине отношения не имеет.
  • Отключение проверки отзыва сертификатов в Windows. Снимает причину B, но ослабляет безопасность всей системы. Правило «amazontrust.com напрямую» делает то же без побочных эффектов.
  • Только домены в прокси-списке. Хаб ищется по IP через UDP, доменные правила его не ловят. Без IP-правил и узла с UDP причина C остаётся.
Собрано 10 сентября 2026 по логам игры и сетевым тестам с одного ПК. Провайдеры фильтруют по-разному, у вас набор причин может отличаться, поэтому начинайте с раздела 2.
